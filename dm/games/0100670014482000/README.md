# Assassin's Creed The Ezio Collection (`0100670014482000`)

Update 1.3 (v196608), SDK 11.4.3, on NVN. **Ubisoft's Scimitar engine** (`scimitar.ini`, `scimitar::g_ThreadLocalData`, `Gear::Thread` workers) with Havok, Wwise and Oodle: the game data in forge archives of Oodle chunks. Modules `main` (31.2 MB of text, build `824b38a2…`) and `sdk` (`4fd34bc9…`). Program 0 holds the collection's menu and Assassin's Creed II. Brotherhood is a program of its own, program 1 (the base NSP carries three more Program NCAs of 31–32 MB beside program 0's), with its data in add-on content 1; Revelations needs add-on content 2, which the dump used here does not have.

**Status: bring-up, not verified.** On the Mac (2026-10-31): the photosensitivity warning, the collection's title screen and its game menu draw correctly at 30 fps; choosing Assassin's Creed II restarts the program inside the host ([ExecuteProgram restarts the program inside the process](../../../docs/reference/services.md#executeprogram-restarts-the-program-inside-the-process)) and AC2 starts: its title screen, its session menu, a new game (name from the system keyboard), the loading screen and the opening cutscene's subtitles. The cutscene's 3D picture was black in that run only because its 247 shaders were not among the libraries built for it. The IPA packs (8.7 GB, add-on content left out). On an iPhone 17 Pro Max (the same evening): the menu, the restart into Assassin's Creed II, a new game and its opening scenes in full 3D at 30 fps, until a crash about 150 s after the restart ([A stage left bound to a freed program](../../../docs/reference/rendering.md#a-stage-left-bound-to-a-freed-program)). With that fixed, a second run went through the Animus's memory loading and the 3D scene of Ezio's birth to the playable escape from the Abstergo lab ("checkpoint reached", Italian subtitles), about 290 s after the restart, without a crash; the stale stage was reported once (`stage 1 was still bound to an object that is no longer a program`). World objects (wall vents, a plant in the Abstergo corridor) were drawn one frame in three: the game culls with bounding cubes whose fragment shader writes visibility flags into one of three rotating image buffers, two of them at pool offsets that are not a multiple of 16, where an Apple GPU wrote the flags 8 bytes early ([Buffer textures at offsets below 16 bytes](../../../docs/reference/rendering.md#buffer-textures-at-offsets-below-16-bytes)). With the image writes redirected through an aligned copy (2026-11-01), bursts of consecutive frames in that corridor show no blinking (A-B-A pixels 0.00%, against 0.9% before).

**Brotherhood and Revelations do not start** `[RED]`. Choosing Brotherhood calls `oe::ExecuteProgram(1, 80 bytes)`: program 1 is not packed, and the game, left waiting to be ended, froze on the iPhone with the menu's music playing (the installed build). The host now restarts program 0 without the parameter instead, back to the collection's start (on the Mac: the collection's title screen again within 100 s, past its warning screen; [ExecuteProgram](../../../docs/reference/services.md#executeprogram-restarts-the-program-inside-the-process)); playing Brotherhood needs program 1 extracted, rewritten, packed and loaded at the restart. Revelations shows **Not Installed** on the collection's menu: `main`'s table of add-on content (`main+0x32b6868`) names index 1 `DLC_EZIO_ACB`, 2 `DLC_EZIO_ACR`, 3 `DLC_EZIO_Sound`, 4 `Video_LINEAGE`, 5 `Video_EMBERS`, and the dump has 1, 3, 4 and 5; A there asks for the eShop (`ec::ShowShopAddOnContentList`, a no-op here) and the menu comes back.

**Closed on 2026-11-01:** the bring-up stops here. The NSPs, the IPA and the shader libraries were moved off this Mac ([Resuming](#resuming)).

## Files

- RomFS: 110 files, 6.7 GB: 27 forge archives (`AC2/DataNX*.forge`, 5.5 GB, version 31; `AC2_PATCH/DataNX_FireFont.forge`), 78 Bink movies (`.bk2`, `.bik`), two Wwise banks (`AC2/sounddata/switch/*.pck`, 0.73 GB), `scimitar.ini`, `localization.lang`. Layout: [01](../../../docs/agents/01-extract.md) and `dm/gfx/tools/forge.py`.
- Add-on content (19 GB in four NSPs): index 1 Brotherhood (10.4 GB: 29 `ACB/DataNX*.forge` archives, 6.8 GB, version 25, its places among them as `DataNX_ACR_Rome`, `_Firenze`, `_Spain`, `_Villa_Past` …; Wwise banks; Bink movies), index 3 AC2's audio pack (3.6 GB of `.pck`), index 4 the film Lineage and index 5 the film Embers (one `.bk2` each, 3.3 GB and 1.3 GB). Pack with `DM_COPY_AOC=NO` and copy it with `scripts/push_aoc.sh` ([settings](../../../docs/settings.md)); the split reads it either way.
- The save is `AC2SAVE`, committed twice in the first seconds.

## Shaders

- **Current:** 46,700 shaders (3,488 vertex, 43,205 pixel, 7 compute): AC2 20,417, Brotherhood's add-on content 26,123, `main` 160 more (program 1's own `main` was not split). The split takes about 50 s ([NVN shader records in Ubisoft forge archives](../../../docs/reference/shaders.md#nvn-shader-records-in-ubisoft-forge-archives)).
- **Where they are:** NVN shader records in the material templates (object type `0xbcfb3c7a`) of the forge datafiles: 224,124 records in AC2's archives, 285,364 in add-on content 1, each a 0x30-byte header, the control section and the code area. `main` keeps the engine's built-in ones the same way (232 records: 66 vertex, 158 pixel, 8 compute whose code area has no header), and the boot uses them: 17 of the 33 shaders drawn up to the game menu.
- **Pairs:** the records name no vertex / pixel pairs (the engine combines them per draw), so every vertex shader is paired with the [single-stage cover](../../../docs/reference/shaders.md#single-stage-programs-paired-with-a-cover): two pixel shaders, 6,976 rows.
- **Compilers:** built with this Mac's Metal compiler 32023.922 (`--allow-other-metal`; the lock names 32023.921).

## On the Mac

- **2026-10-31, headless runs of `dmhost`** (`DM_NVN_SHOT` screenshots; the shader libraries of the 35 shaders the boot asks for, built alone with `own_compilers.py`, as the full Mac build takes hours): `nnMain` at once, the RomFS image mounted, no add-on content offered (no `DM_AOC_DIR`), the NVN device up with window origin upper left and depth mode near = 0, `AC2SAVE` mounted and committed twice, two audio outputs. The warning screen at frame 600, the title screen by frame 2600 (90 s), the game menu after A (frame 3000). 33 shaders by then, all in the map, none failing to load: 17 from `main`, the rest from `DataNX.forge`, `DataNX_Abstergo.forge` and `DataNX_WhiteRoom.forge`.
- **Frame time:** 30 fps, p50 33.2 ms, p95 85.7 ms on the menu (M5, GPU p50 7.2 ms; the longer frames are the menu's streaming). Resident memory 1.86 GB, GPU allocations 1.35 GB; the heap is 3.13 GB.
- **SDK 11.4.3:** the same SDK as [Metroid Dread](../010093801237C000/README.md) and [13 Sentinels](../01003FC01670C000/README.md), with another `sdk` build (`4fd34bc9…`, theirs is `2d369d99…`): the SDK-wide cuts apply by function match (the AddressRegionManager node area and the 1 GB region alignment, `patched_*/sdk.match.tsv`). The host answers NVN API 55.15 and the game creates its device. Of the 537 NVN names the null device knows, 434 are implemented; the game called none of the other 103 up to the menu.
- **Starting Assassin's Creed II (restart):** A on the collection's title, A on the AC2 page: `oe::ExecuteProgram(0, 100 bytes of parameters): restarting the program inside this process`; every guest thread ended in 8–12 ms; the old program's NVN objects were finalized (421 memory pools, 204 textures, 351 buffers, 48–59 programs, 44 samplers, 320 command buffers, 93 syncs, 5 queues, 1 device) and its AudioOut closed; the reset took 70–100 ms. The program entered `nnMain` again and popped the 100-byte launch parameter at once, then opened its window, renderer and audio again: AC2's title screen by frame 6000, its session menu after A. The `DM_KEYS` frame count goes on across the restart.
- **Into a new game:** "Create new game" opens the system keyboard for the save's name (initial text `Desmond`); a headless run cancels it unless `DM_KBD=Desmond` gives the text. With it: the loading screen (the Animus icon, frame 8,100) and the opening cutscene's subtitles (frame 11,400), no crash to frame 12,300. The 3D scenes need 247 shaders the partial libraries of that run lacked (a full Mac build has them).
- **Red lines:** `stage 1 cb2 has no uniform buffer bound` once at the first menu frame; the partial libraries' missing stamp (`c1_full.tsv`, a full build makes it).

## iPhone

- The IPA (8.7 GB: the RomFS, 46,700 iOS shader libraries, a pipeline archive for `g18p`) packs with `DM_COPY_AOC=NO`; the add-on content stays in `<title ID>_build/aoc` for `scripts/push_aoc.sh`. The first one (`AssassinsCreedTheEzioCollection.ipa`) predates the program restart and `depth_mode zero`; `AssassinsCreedTheEzioCollection-restart.ipa` has both. Not run on a phone here.
- Installed on an iPhone 17 Pro Max (2026-10-31) from this Mac, not launched. `devicectl device install app` refuses the IPA itself (ad-hoc signature: `0xe8008014`, "The executable contains an invalid signature"), so the app from `-restart.ipa` was installed without its `romfs.img`, signed with an Apple Development identity and the game's development profile (`increased-memory-limit` included). The RomFS went to `Documents/romfs.img` (`scripts/push_romfs.sh`, from `extract/v196608/RomFS.img`; the bundle has no `romfs.id`, so any complete image is used) and the add-on content to `Documents/aoc` (`scripts/push_aoc.sh`: 3, 1, 4, 5).

## Open

- **Brotherhood:** program 1 is not packed `[RED]`. It needs `nx_extract` to take a program index (it takes the lowest title ID, program 0), the rewriter and the shader split to run on program 1's modules, the app to carry both programs' code, and the restart to load program 1's modules in place of program 0's.
- **Revelations:** needs add-on content 2 (`0100670014483002`, mounted as `DLC_EZIO_ACR`), then presumably its own program, as Brotherhood (not checked).
- **The build on the iPhone** is the last one installed (2026-11-01, the flicker fix): it has neither the restart of program 0 for another index nor anything later, so choosing Brotherhood there still freezes with the menu's music.
- **Gameplay on the Mac:** AC2's scenes need the full Mac shader libraries (`--platform mac`), about 2.5 hours to compile here; the iPhone build has its libraries.
- **Returning to the collection's menu** from a game presumably restarts program 0 the same way (not checked).
- **Memory keys:** still the survey's guesses; not measured in a level.
- **Pipelines:** `pso_manifest.tsv` is empty (nothing recorded yet); the pairs are the single-stage cover only.

## Resuming

The extracted files, the add-on content images and the builds were removed from the Mac it was brought up on. To go on: put the base game, the 1.3 update and the add-on content NSPs in one folder and run the packing script (extraction, the add-on content and the rewrite take minutes). A copy of the old `<title ID>_build/shader` folder put back first spares most of the 46,700 iOS shader compiles, which are reused while the translation chain is unchanged ([reuse](../../../docs/development.md#the-packing-script-in-detail)).
